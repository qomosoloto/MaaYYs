# 寮突破模块

## 目的

自动完成阴阳寮结界目标选择、进攻、战斗结算和异常恢复。

## 模块概述

- 原版入口：自动寮突破 / 寮突
- 实验入口：自动寮突破 V2（实验版）/ 寮突V2
- Pipeline：resource_pack/base/pipeline/战斗/
- 自定义识别：GuildBarrierTargetRecognition

## 规范

### 需求：原版与 V2 并行

原版 Pipeline 和任务入口保持不变；V2 使用独立节点命名空间，并可复用图片素材和参数化 agent 能力。

### 需求：状态驱动的场间切换

V2 点击战斗结算后等待突破列表特征实际出现，再按当前进度选择目标。正常路径不使用固定约 18 秒的组合等待。

### 需求：异常恢复

V2 保留“该结界已被攻破”短暂提示和实际进攻后的同一玩家持续停留保护。只有玩家名与进攻按钮成对识别成功且已经点击进攻，才建立观察窗口；同一目标持续至少 6 秒且连续命中后才进入恢复流程。

进攻前不使用旧的末尾玩家 OCR 连续计数器。目标弹窗未稳定、玩家名或进攻按钮任一未命中时，本轮识别失败并重新判断界面状态，不得关闭并重进结界突破。

## 依赖

- MaaFramework Pipeline 协议
- GuildBarrierTargetRecognition
- OCRResultCounterRecognition
- ClearHitCount

## V2 状态流

1. `寮突V210` 或 `寮突V28` 识别战斗结果、记录带玩家名的成功或失败日志，并先使用常规控制器点击结算界面。
2. 常规点击后仍存在“点击屏幕继续”时，`寮突V2-继续点击战斗结算` 动态定位游戏所在 Android display，按 OCR 状态使用指定 display 的 ADB Shell 限频补点；补点受结果节点 60 秒状态窗口约束，不设置任务生命周期命中上限。
3. `寮突V2-结算后列表就绪` 以 500ms 限频识别“击败次数”，最长等待 30 秒。
4. 列表就绪后按全破、已有进度、零进度分流，选择尚未击破的目标。
5. 从宽范围 OCR 结果取得实际进攻按钮框，按按钮中心横坐标匹配左侧或右侧玩家名；两者成对命中后由同一自定义识别节点记录目标并单次点击进攻。
6. 若实际点击后的目标持续至少 6 秒且累计至少 3 次识别仍未进入战斗，执行关闭并重新进入阴阳寮突破的恢复流程。

## 2026-08-30 未进攻循环根因与修复

### 现象

V2 选择一个目标后打开进攻弹窗，却没有点击“进攻”；随后关闭目标弹窗、关闭整个结界突破、重新进入并再次选择同一目标，循环往复。

### 根因

- 宽范围 OCR 已识别到右侧“进攻”按钮，但原先的右侧窄 ROI 将按钮误识别为其他文本，单次点击节点没有命中。
- 记录节点在没有识别到有效玩家名与按钮配对时仍返回成功，旧的末尾玩家计数器继续累计背景列表中的同一玩家。
- 计数器达到阈值后误判“当前结界已被攻破”，触发关闭和重进流程。

### 修复约束

- `reset` 支持 `require_target: true`；玩家名与按钮不能成对识别时返回失败，不创建观察状态。
- 自定义识别返回实际进攻按钮框，并由 Pipeline 的 `action: Click` 直接完成一次点击，避免识别与点击使用不同 ROI。
- 左右目标共用已验证的宽范围进攻按钮 OCR，以按钮中心横坐标 `< 640` 或 `>= 640` 匹配对应玩家名。
- 移除 V2 进攻前的旧末尾玩家计数器；保留实际进攻后的 6 秒持续目标恢复保护。
- 四个目标选择节点点击后等待 1 秒，让弹窗动画稳定后再识别目标与按钮。

## 2026-08-31 胜利后任务失败根因与修复

### 现象

V2 已经进入战斗并取得胜利，胜利结算页停留在“点击屏幕继续”，运行日志最终显示任务失败，且没有输出对应的攻击成功日志。

### 根因

- 点击进攻后约 0.37 秒，目标弹窗仍未完全消失，弹窗背后的“击败次数”OCR 区域已经可见。
- 进攻节点的候选列表包含 `寮突V29`，该节点把背景“击败次数”误当成已经返回目标列表，清理计数后通过 JumpBack 回到进攻按钮和目标记录节点。
- 战斗期间目标记录节点无法识别玩家弹窗，20 秒后触发 MaaFramework 的 `error handling loop detected`，导致整个任务失败。
- 同一帧日志证明 OCR 已识别到 `点击屏幕继续` 和“胜利”，但错误的状态分支使成功结算节点没有执行机会。

### 修复约束

- 从实际点击进攻后的候选状态中移除 `寮突V29`；弹窗背景的列表文字不能作为战斗已经结束的证据。
- 进攻后的 Pipeline 超时设置为 600 秒，覆盖正常战斗时长，只由已攻破提示、同一目标持续停留、失败结算或成功结算推进状态。
- 成功结算继续使用已由实测日志命中的 `点击屏幕继续` OCR，并在点击结算时记录攻击成功日志。

## 2026-08-31 成功日志后仍停留结算页的输入链路修复

- 实测确认成功 OCR 返回框为 `[555,676,171,31]`，MaaFramework 在该框内点击 `[647,677]`；点位距离 720 高度底边仅 43 像素，动作回调成功但游戏没有切换页面。
- 胜负结果节点不再点击 OCR 文字框，最初改用仓库 `自动结界` 的大范围结算区域 `[242,542,893,178]`；后续实测发现该区域仍可能点中加成说明弹窗。
- fix3 实测确认 MaaFramework 的 `MuMuPlayerExtras` 多显示输入可能报告触摸成功但画面无响应，因此增加指定 Android display 的 ADB Shell 兜底。
- `寮突V2-继续点击战斗结算` 从 `dumpsys activity activities` 动态取得阴阳师所在 display，再从 `dumpsys input` 读取逻辑尺寸并按相对坐标点击；无法解析时回退到 display 0 和 1280×720 基准。
- Shell 兜底最初最多执行 3 次；后续已取消任务生命周期命中上限，改由 OCR、1 秒限频和结果节点 60 秒状态窗口约束。
- 胜负结果节点显式设置 60 秒超时，避免其等待“结算后列表就绪”时被 MaaFramework 默认 20 秒超时提前终止。

## 2026-08-31 三次补点耗尽后的结算死锁修复

### 现象

V2 已记录攻击成功，OCR 持续准确识别“点击屏幕继续”，Shell 动作也返回成功，但三次补点均未让游戏切换页面；此后任务每 60 秒超时一次，始终停在同一结算画面。

### 根因

- Shell 退出码为 0 只表示 Android 接受了 `input` 命令，不代表游戏一定消费了该次触摸。
- `max_hit: 3` 以 Maa 任务生命周期累计；三次用尽后恢复节点永久不可再执行，而命中计数只有在突破列表已经出现后才会清理，形成不可达的循环依赖。
- 同一运行日志也存在两次 Shell 补点后成功返回列表的样本，证明 OCR 与 display 定位链路有效；后续双实例复现表明高度 70% 的逻辑坐标并不是稳定的安全点。

### 修复约束

- 保留 OCR 判断“点击屏幕继续”，避免在非结算界面发送补点。
- 保留动态 Android display 和逻辑 viewport 定位；桌面端拖动或缩放模拟器窗口不影响内部坐标。
- 移除补点节点的 `max_hit`，由结果节点的 60 秒状态窗口、1 秒限频和 OCR 命中共同约束重试。
- Shell 标准输出记录 `display_id`、`viewport` 和最终点击坐标；后续可直接从 MaaFramework 日志区分坐标解析错误与游戏未消费触摸。
- 胜利与失败结算共用同一恢复链路，原版 `寮突.json` 保持不变。

## 2026-08-31 结算说明弹窗坐标修复

### 现象

两个 MuMu 实例都稳定停在带有“战斗胜利获得的金币增加”说明的结算画面。日志持续输出 `viewport=1920x1080 tap=960,756`，OCR 仍能识别“点击屏幕继续”，但点击没有关闭结算页。

### 根因

- 旧 Shell 坐标使用画面高度的 70%；在 1920×1080 逻辑画面中得到 `(960,756)`，恰好落在中央黑色加成说明弹窗内部。
- 胜负节点的常规点击范围 `[242,542,893,178]` 同样覆盖该弹窗，随机点位仍可能被弹窗消费。
- 问题与桌面窗口位置或缩放无关；ADB 输入使用 Android display 的逻辑 viewport 坐标。

### 修复约束

- 胜负结果节点的常规点击范围收窄为 1280×720 基准下的底部安全带 `[600,684,80,20]`。
- Shell 补点改为宽度 50%、高度 95% 的相对坐标；1920×1080 实例解析为 `(960,1026)`。
- 两个实例分别在 `display 0` 与 `display 2` 手工发送新坐标后，均立即离开结算页并继续选择下一目标。
- 保留 OCR 门控、动态 display 解析、1 秒限频和诊断日志；不修改原版 `寮突.json`。

## 参数兼容

- `target_layouts` 和 `log_prefix` 均为可选参数；原版未传入时使用原版左右布局和 `寮突破` 日志前缀。
- V2 显式传入自己的节点布局和 `寮突破 V2` 前缀，避免识别器内部引用原版 Pipeline。
- `require_target` 默认关闭以兼容原版；V2 的进攻节点显式开启，确保识别结果可直接用于点击。
- `attack_center_x_min` / `attack_center_x_max` 用于共享按钮识别节点与左右玩家名的空间配对。
